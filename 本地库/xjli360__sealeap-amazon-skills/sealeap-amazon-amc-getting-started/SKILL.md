# SeaLeap AMC 入门与应用规划

先用一个明确业务问题理解 AMC，再确认它能读取什么、输出什么、如何连接到广告行动。

## 输入

品牌/店铺、站点与广告 profile、业务规模和目标、现有 SP/SB/SD/DSP 使用情况、AMC 实例/权限、可用数据及时间范围、技术资源与费用约束。

## 工作流

1. 在当前广告控制台核对 AMC 入口、资格、权限与条款状态。视频路径为“衡量和报告 > 亚马逊营销云”，首次界面有 Agree and continue；实际新条款不能仅因出现在教程中就自动接受。
2. 明确一个问题，例如广告组合触达是否重叠、转化路径多长、频次是否过高、哪些已互动人群可形成后续实验。
3. 区分衡量、洞察、受众与投放：AMC 的分析/受众结果本身不会自动修改所有广告活动，也不能证明无转化触点产生了因果增量。
4. 检查首页、Insights、Use cases 与可用帮助资源，记录真实存在的入口及字段。没有权限或数据时给准备清单，不编造屏幕、结果或 SQL。
5. 利润型卖家先选择成本与组合衡量，品牌型卖家可加入触达与新客问题；业务规模不直接决定必须使用某个广告产品。
6. 输出一个分析方案及可能衔接的广告实验。SP/SB 的受众竞价调整与 SD/DSP 的受众定向分别核验，避免混淆控制范围。

## 交付

AMC 准备度、入口与功能定位、首个问题及数据需求、衡量口径、受众/广告应用路线、权限或内容缺口和下一步可验证任务。

## 证据与执行范围

- 材料中的案例、比例和时间表标为 `COURSE_BASELINE` 或 `TRAINING_CASE`；来源与口径已核验的店铺数据标为 `ACCOUNT_FACT`，用户转交但未核验的数据标为 `USER_PROVIDED`，合成练习标为 `SIMULATED`。推断标为 `HYPOTHESIS`，缺失项写 `UNKNOWN`，不补成 0。
- 先固定店铺、广告 profile、站点、ASIN、币种、数据窗口与归因口径。课程介绍的资格、界面、报告字段和功能覆盖在实际使用时核验。
- 默认交付诊断与草案。真实写入只在当前会话已授权的对象、动作和预算内执行，并保存旧值与回读结果；新增范围先取得授权。
