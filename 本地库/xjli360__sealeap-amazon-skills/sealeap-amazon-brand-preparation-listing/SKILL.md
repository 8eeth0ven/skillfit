# SeaLeap 品牌筹备与多语言 Listing

解决品牌筹备阶段“页面怎么表达、谁在买、为什么买、如何本地化”四类问题。先形成证据链，再让 AI 生成文案或素材。

## 输入

产品规格与限制、可证明卖点、品牌定位、目标站点/语言、现有 Listing/A+、合法取得的聚合客户画像、真实反馈与评论主题、关键词及当前内容规范。团队人数只是背景，不是阶段判定硬门槛。

## 工作流

1. 依据页面基础、经验与广告状态确认是否处于筹备型任务。已成熟品牌的单个新品也可单独执行页面准备。
2. 区分人口统计与购买场景：从“谁购买”继续查“在何处、何时、为谁、完成什么任务”。用评论/客服/退货等实际证据反证初始想象。
3. 建立卖点—证据—场景—页面位置矩阵，优先补齐可信的规格、兼容性、限制和品牌信息。
4. 按账户当前能力选择关键词、图片或自有/获准 URL 作为 AI 输入。生成标题、五点、描述或 A+ 后逐条核验，删除没有事实依据的承诺。
5. 多语言任务使用“需求与边界、参考材料、检查调整”的提示结构。核验关键词、单位、自然表达、当地使用场景和品牌一致性，保留双语修改说明。
6. 检查“管理您的试验”等工具资格，设计一个主要页面变量的验证。工具不可用时采用有局限的前后观察，并记录价格、广告、库存等干扰。

## 交付

- 画像与场景证据表及尚未解决的矛盾。
- 卖点矩阵，标明事实、来源、限制与页面位置。
- 各语言标题/五点/描述、A+ 模块及图片/视频简报。
- 关键词覆盖、声明核查、翻译审校清单与页面实验卡。

## 证据与执行范围

- 材料中的案例、比例和时间表标为 `COURSE_BASELINE` 或 `TRAINING_CASE`；来源与口径已核验的店铺数据标为 `ACCOUNT_FACT`，用户转交但未核验的数据标为 `USER_PROVIDED`，合成练习标为 `SIMULATED`。推断标为 `HYPOTHESIS`，缺失项写 `UNKNOWN`，不补成 0。
- 先固定店铺、广告 profile、站点、ASIN、币种、数据窗口与归因口径。课程介绍的资格、界面、报告字段和功能覆盖在实际使用时核验。
- 默认交付诊断与草案。真实写入只在当前会话已授权的对象、动作和预算内执行，并保存旧值与回读结果；新增范围先取得授权。
