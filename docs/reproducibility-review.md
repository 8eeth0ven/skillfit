# SkillFit 可复现性复核

复核日期：2026-10-29。范围：本地仓库的 README、执行器、采集器、示例任务与网站快照结构。没有启动 `run`、`score`、`doctor`、采集循环或全库重新聚合；没有改动历史产物、评分或网站数据。

## 核心结论

旧版快速开始不能作为新用户的可靠入口：克隆地址是占位符，运行根目录硬编码到作者桌面，示例技能清单使用作者本机绝对路径，示例清单文件名与执行器读取的名称不同。根线程已为本次优化补上可移植根目录、相对技能清单和独立离线示例。离线示例可以复现提示词构造和断言检查；它不证明技能有增益。

规模数据也需要分清口径。本次只读查看的**本地工作区快照** `site/data.json` 标记为 `2026-10-29 01:28:25`，包含 2,652 个技能条目和 71 个同类对比组；仅 1 个技能存在非空 `gains`、`m1_mean` 和 `m4_mean`。这些计数说明当前本地展示数据以 M2 扫描为主，不能推导“全量技能都完成四模式对照”，也不能据此判定模型是否替代了技能。本地该文件本就有未提交改动，本复核未覆盖它，也未把这些计数当作远端仓库快照。

## 发现与本次处理

| 优先级 | 发现 | 影响 | 本次状态 |
|---|---|---|---|
| P0 | 原 `bench.py`、`collect.py` 的 `PROJ` 固定为作者桌面目录 | 在其他目录克隆后仍会读写原位置或找不到任务 | 根线程改为脚本所在仓库，支持 `BENCH_ROOT`；临时根目录复核通过 |
| P0 | 原示例清单名为 `skill-files.txt`，执行器只读取 `技能文件.txt`；humanizer 清单还引用个人绝对路径 | 复制示例不能直接运行 | 根线程兼容两种清单名并解析相对路径；新增自包含 `format-check` 示例 |
| P0 | 旧 README 用 M2 高分支持“最佳契合”并暗示普遍实测增益 | 模型本身强、技能无帮助也可能高分 | README 应分开绝对质量、配对增益和覆盖率；完整效用判断交给增益审计 |
| P1 | `doctor` 实际调用模型，`run`/`score` 也消耗通道额度 | “健康检查”容易被误解为离线检查；免费通道不是永久零成本承诺 | 根线程新增离线 `preview`，文档应明确各命令成本边界 |
| P1 | M1 的评分权重与 M2 不同，M2 有技能遵循维度 | 历史总分差混入量尺变化，不能直接作为干净的因果增益 | 需要使用共同结果质量维度重新计算，或用同一客观验收规则；不能只改宣传措辞解决 |
| P1 | M4 以字符数控制材料长度，而且技能指令与背景材料的引导语不同 | 不是 tokenizer 精确等长，也不能把 `M2−M4` 直接解释为纯技能内容的因果效应 | 根线程补足字符长度与缺省填料；对照解释仍需保留限制 |
| P1 | 原聚合以 `(model, task, mode)` 为键 | 多 trial 会覆盖或丢失重复信息，单次高分不是稳定性证据 | 本次新增审计工具负责区分任务、重复与判官；历史聚合结果仍需谨慎解释 |
| P1 | M2 明确禁止工具，并把外部脚本/文件视为无需执行 | 无法验证真正依赖工具、脚本、私有数据的工作流技能 | 应称文本通道扫描；工作流执行验证属于后续独立评测 |
| P2 | 原常驻脚本依赖个人安装目录中的执行器；网页刷新扫描旧评分目录 | 不能承诺任意克隆环境均支持 7×24 常驻流水线 | 已改为仓库相对执行器并统一 scoring/；README 提供单次 CLI 流程，循环脚本保持可选 |

原采集器还在解析参数之前写入单实例锁，因此 `collect.py --help` 原本也会产生锁文件。应把锁获取放在 `parse_args()` 后，让帮助命令保持只读。此问题已修复，帮助命令不再写入锁。

## 实际验证

运行了以下离线命令，均退出为 0：

```bash
python3 tools/bench.py --help
python3 tools/collect.py --help
python3 tools/bench.py check --skills humanizer
codebuddy --help
codebuddy --version
```

`check --skills humanizer` 读取的是作者已有运行数据，只验证断言层可执行。它不验证新用户能直接运行 humanizer，也不证明任何模型当前优劣。

另在临时目录设置 `BENCH_ROOT`，在仓库以外的工作目录，用执行器的绝对路径依次运行：

```bash
python3 "$SKILLFIT_REPO/tools/bench.py" init-example --name format-check
python3 "$SKILLFIT_REPO/tools/bench.py" preview --skills format-check --modes M1,M2,M4
python3 "$SKILLFIT_REPO/tools/bench.py" check --skills format-check
```

这三步均退出为 0。示例产生 2 个任务、每个 6 个断言，`preview` 构造出 6 个任务/模式提示词。临时根目录仅有复制的 4 个示例文件，没有产生 `runs`、`scoring`、`reports` 台账。`check` 在尚未运行模型时只输出表头，这是预期行为。

## 推荐的快速开始边界

1. 新用户先克隆真实仓库地址 `https://github.com/8eeth0ven/skillfit.git` 并查看静态 `site/`；静态查看不需要 CodeBuddy 或 API key。
2. 用 `init-example` 与 `preview` 验证路径、任务、技能清单和断言，不请求模型。该流程需要 Python 3；执行器使用 `fcntl`，原生 Windows 需要 WSL 或适配。
3. 真正评测前确认本机 CodeBuddy 当前可用模型 ID；旧快照中的模型名称不是可用性承诺。API 通道使用 `/v1/messages` 和 Anthropic 风格消息，不宜笼统写成任意 OpenAI 兼容端点；API 分支另依赖 `urllib3`。
4. API key 模板需要通过 `source secrets.env` 或其他方式导出环境变量；仅复制模板文件不会自动加载。现有本地凭据文件本次未读取。
5. 从一个技能、少量匹配任务开始，使用相同任务、模型版本、评分规则、工具与预算比较 M1/M2，再加入 M4；先看配对覆盖与失败，再解释分差。
