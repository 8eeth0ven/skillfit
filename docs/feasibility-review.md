# SkillFit 可行性复核与模型替代风险

复核日期：2026-10-29。范围：本次修改前的 `README.md`、`tools/bench.py` 与本地 `site/data.json`，以及下列公开一手资料。本报告评估的是项目方向和证据能力；没有运行新的模型横评，也没有验证付费意愿。

## 判断

**有条件可行。优先发展“技能净增益与退役评估”，收缩“通用技能绝对分数排行榜”。** 模型升级会吸收一部分通用提示技巧，但不会消除用户在升级后判断哪些技能仍有用的需求。这个需求是合理假设，商业价值仍需用户试验验证。

长期交付物应是一份可复核的决策：在某个模型版本、执行环境和任务分布下，这个技能应保留、压缩、重写还是停用。静态高分、采集数量、交叉判官数量和 3D 展示本身都不能证明这种价值。

## 哪些容易被模型吸收

| 技能内容 | 替代风险 | 对 SkillFit 的含义 |
|---|---|---|
| 通用写作套路、常见代码建议、简单角色提示 | 高：通用能力和默认指令改善后，额外文档可能变成负担 | 每次模型升级重新测裸跑基线，允许得出“无需加载” |
| 公开且稳定的领域知识、常用库调用说明 | 中高：模型训练、检索与工具帮助可能覆盖 | 加入简短直接指令或官方文档检索基线，评估技能是否值得维护 |
| 高频且固定的多步流程 | 中：模型能够规划流程，但稳定执行和验收仍可能有差距 | 测完成率、失败恢复与时延，避免只评价回答是否像流程 |
| 可执行脚本、模板、格式校验器 | 较低的整体替代风险，但某个包装形式仍可能过时 | 测完整执行结果，并和直接调用脚本比较；区分脚本价值与提示包装价值 |
| 组织私有术语、内部规则、近期政策与业务系统上下文 | 较低的知识吸收风险，但可被其他上下文机制承载 | 机会在企业本地回归与配置选择，不能宣称 `SKILL.md` 是唯一载体 |
| 权限、真实系统接入和可审计的验收程序 | 基础模型不能单独提供外部状态与接入；平台能力仍可能替代包装 | 固定工具和权限条件，测执行链；把接入价值与模型能力分开 |

Agent Skills 标准将技能定义为可携带指令、脚本、参考材料和模板的文件夹，并明确包含团队、公司和用户上下文。这支持“技能不等于一段通用提示词”的判断，也意味着仅评 `SKILL.md` 文本不能覆盖整个对象。[Agent Skills 官方概览](https://agentskills.io/home)

Anthropic 的说明把按需加载、确定性代码执行与从失败任务出发的迭代评估作为技能设计要点。由此推断：可复用执行资产和真实工作流仍可能有价值，前提是实验确实执行了这些资产。[Anthropic：Equipping agents for the real world with Agent Skills](https://www.anthropic.com/research/equipping-agents-for-the-real-world-with-agent-skills)

## 影响结论的实现问题

以下描述检查起始版本；修复代码后仍需要重跑或从原始判分重新计算，旧结果不会自动获得新方法的有效性。

1. **对照不在同一评分尺度。** 起始版 `WEIGHTS` 对 M1 使用正确性/完整性/表达的 `.55/.30/.15`，对 M2 使用 `.40/.25/.20/.15`，其中 `.20` 为技能遵循。M4 没有技能文档，该项通常为 `null`，`weighted()` 又按现有维度重归一化。因此 `M2−M1`、`M2−M4` 可能混入权重变化。应以同一结果正确性与完整性口径比较各模式，把技能遵循列作诊断。
2. **M2 是纯文本条件。** `cell_prompt()` 明确禁止读取文件、执行脚本或调用工具，并将外部资源视为不需要。这可以评价文本指导的效果，不能称为对完整 Agent Skill 的执行评估。工具任务需要同权限、同资源、同验收的独立执行轨。
3. **M4 只按字符数截断。** 无关技能材料不保证 token 数相等，也可能带来干扰或额外知识。`M2−M4` 是相对该对照的差值，不能无条件称为“纯内容因果增益”；`M4−M1` 同样可能是增益或损害。应披露 tokenizer、控制材料及其版本，并做多个控制文本的敏感性分析。
4. **SkillScore 主要是绝对表现。** `.60` 权重来自 M2 均分；没有 M3 时直接给触发部分一半分数。它不能证明技能贡献，也不应替代增益指标。一个裸跑已完成的任务，加载技能后继续高分，不构成技能有效的证据。
5. **多试验配对需要显式保存。** 起始版聚合的 `totals[(model, task, mode)]` 没有 trial 维度，多个试验会覆盖；`by_model` 又累加各次结果。应先固定任务与 trial 配对，再以任务为统计单元汇总，不把同一任务的重复试验当成额外独立任务。
6. **跨技能比较需要同任务内容与同模型。** `cmd_cross()` 以任务名称对齐，并把各技能的明细压到 `{任务: 总分}`，可能覆盖不同模型或试验。共同的 `T01-快扫` 名称不足以证明输入相同。应使用任务内容哈希，并保留模型、执行环境、trial 与验收版本。
7. **匿名和多判官有边界。** 隐去模型名与哈希代号可以减少直接身份提示，不能排除风格识别、自偏和相关错误。PoLL 论文支持使用多样化评审面板，但没有证明“家族平均再取中位”的本项目实现必然无偏。应保留确定性验收、人工抽查与不确定性。[PoLL 原论文](https://arxiv.org/abs/2404.18796)

README 中的“学术基准只评模型”“吸收并超越”“抄不走”与“约零成本”应收回或改为带条件说明。免费额度仍有配额、时间与维护成本；本机存在循环脚本也不能证明用户环境始终 7×24 正常运行。

## 竞争位置与可持续价值

SkillsBench 已经公开 with/without skills 的配对比较，页面显示模型与 harness 组合、置信区间、时间与能力变化。其论文和版本化任务包还提供确定性验收及任务摘要。SkillFit 不能把“实测技能有效性”本身当成独占定位。[SkillsBench 官方](https://www.skillsbench.ai/)、[SkillsBench 论文 v4](https://arxiv.org/abs/2602.12670v4)、[v1.1 任务包发布](https://github.com/benchflow-ai/skillsbench/releases/tag/v1.1)

可争取的差异化是更贴近配置维护：用户导入自己的技能和工作任务，模型升级后只复测受影响配对，输出保留/压缩/重写/退役的证据。价值来自版本化任务、可信验收、历史回归、运行集成与用户累积数据；漂亮的榜单与自动生成的评分叙述容易被复制。

首批用户可以选择两类：维护多个模型渠道的团队，以及持续发布技能包的作者。前者关心升级与运行成本，后者关心某次改动是否造成回归。两者应分别验证，不能仅用 GitHub star 或技能采集数量当作需求证明。

## 最小可证伪试验

下列数字是建议的试点门槛，应在看到结果前固定；它们不是已经取得的实验结果。置信区间按任务进行配对重采样，重复试验先在任务内聚合。样本不足或区间过宽时结论是“不确定”，不是“被替代”。

| 试验 | 最小设计 | 预设的继续/停止条件 |
|---|---|---|
| 1. 模型是否已吸收通用提示 | 选 6 个通用提示技能和 6 个含脚本/模板/私有规则的技能，每个 10–20 个保留测试任务；固定 2 个可锁定版本的模型，M1/M2 各 3 次；结果用同一验收 | 若通用类在至少两个模型版本上，增益 95% 区间整体处于 ±5 个百分点，且没有成本或时延优势，则将该类标为退役候选；区间跨越界限则补样本。不要用“不显著”代替等效证据 |
| 2. 完整技能是否优于简短指令 | 对有正增益候选加入简短直接指令、仅脚本、完整技能三组；资源与权限一致，记录正确率、费用与 p50/p95 时延 | 若简短指令达到预设质量容差且更便宜或更快，推荐压缩；若仅脚本已达到相同效果，说明执行资产有价值而包装增益未证实 |
| 3. 增益是否经得住控制变化 | 使用相同任务/判官/结果尺度，增加至少两种长度与位置匹配材料，盲化条件次序；确定性验收为主 | 若结论随无关材料或判官选择而翻转，停止发布“纯内容增益”认证，保留探索性结果并调整任务与控制 |
| 4. 模型升级是否真的改变决策 | 固定技能提交、任务哈希、harness、工具版本与预算，比较升级前后裸跑和带技能；只在可固定版本时声称纵向变化 | 至少发现可复核的保留/压缩/退役变化，才支持“升级回归服务”定位；若没有稳定差异，暂缓自动退役和路由产品 |
| 5. 团队是否愿意持续使用 | 找 3–5 个有真实技能维护负担的团队，手工交付一次本地报告，再跟踪下一次升级/技能修改是否复测 | 以节省的人工检查时间、被实际采纳的配置改动和主动复测为成功指标；若没有复测需求或可执行决策，暂停扩建全库常驻排名，重新选择场景 |

决策需要同时看效果与成本。技能即便没有提升最高正确率，也可能让小模型以更低成本达到目标；反之，微小分数提升可能抵不过长上下文与执行时延。缺失 token、计费或工具用时记录时，只能输出“成本未知”。

## 优先级

**P0：让现有结果可解释。** 明确当前覆盖与限制；区分绝对表现和净增益；修复同尺度评分、trial 配对与缺失数据处理；将模型别名、技能文本和任务内容绑定到具体版本。旧结果标为历史快扫，不按新协议追认。

**P1：用小规模任务证明决策价值。** 先做上述 12 个技能的代表性试点；工具轨必须实际运行脚本和产物验收。优先发布证据完整的配对卡，显示覆盖、净增益、不确定性和成本状态。对缺少对照的条目明确输出“证据不足”。

**P2：验证维护工作流。** 支持用户任务导入、技能提交前后比较和模型升级复测。先服务少量团队，形成可追溯数据。是否建设动态路由、常驻调度、认证徽章或商业服务，取决于试点是否产生反复使用的决策价值。

**暂缓：** 扩大廉价 M2 快扫规模、全量 N×N 判官常驻与继续增加榜单视觉复杂度。它们能增加数字，却不能补上缺少裸跑对照和真实执行验收的问题。
