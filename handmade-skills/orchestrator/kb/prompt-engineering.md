# prompt 工程（subagent 侧）

本篇解决四个问题：怎么写 subagent prompt、怎么压缩上下文、怎么断点续跑、怎么聚合结果。
入口：SKILL.md 短表 prompt-engineering.md 各行。

## §1 subagent prompt 模板（五要素）

下发模板（直接抄，尖括号整体替换）：
```
【目标】<一句话，动词开头，说清做成什么>
【输入】<文件绝对路径列表 / 数据格式说明 / 主线程已掌握的结论摘要——只给结论不给大段原文>
【产出格式】
- 落盘：<产物文件绝对路径 + 格式（md/json/csv）；表格给表头示例>
- 回复：≤200 字摘要 = 完成清单 + 关键结论 + 产物路径
【完成标准】<可验证条件：产物条数 / 测试通过 / lint 无报错 / 覆盖全部输入>
【禁止】不得改动范围外文件；不得通读整个仓库；不得在回复里粘贴大段产物内容
```

自检：五要素逐个打勾，缺任何一个就不发（每个缺口的翻车症状见下表最右列）。

五要素逐项正反例：

| 要素 | 正例 | 反例 | 反例的翻车症状 |
|------|------|------|----------------|
| 目标 | 「提炼 api/ 下所有接口的鉴权方式，落成鉴权表」 | 「看一下 api 目录」 | subagent 自由发挥，产出对不上需求 |
| 输入 | 「输入：/data/js/urls.txt（每行一个 URL，共 87 行）；已知：站点为 SPA，接口在 /api/v2 前缀下」 | 「输入是我们之前找到的那些文件」 | subagent 找不到输入 → 重新探索全仓库 |
| 产出格式 | 「写 /out/鉴权.md，表头 `接口|鉴权方式|是否生效`；回复只给行数＋3 条代表结论」 | 「把结果发我」 | 大内容回传 → 主线程上下文爆 |
| 完成标准 | 「87 行每行鉴权列非空，无 TODO 占位」 | 「做完就行」 | 半成品也敢回「完成」（假完成） |
| 禁止 | 「禁止改 src/ 下任何文件；禁止跑网络扫描」 | （不写） | subagent 越权改代码、干了范围外的活 |

填好的完整实例（对照感受信息密度）：
```
【目标】统计 /data/logs/ 下 12 个 jsonl 日志中每个 user_id 的请求次数与错误率，落成一张表
【输入】/data/logs/*.jsonl 共 12 个文件，每行一条 JSON：{ts,user_id,path,status}；时区均为 UTC
【产出格式】写 /out/用户统计.csv，表头 user_id,requests,errrors,err_rate；回复 ≤200 字：行数＋错误率最高的 3 个 user_id＋文件路径
【完成标准】所有 user_id 都出现在表里且 requests>0；err_rate 介于 0-1；csv 可被 pandas 直接读
【禁止】不改 /data/ 下任何文件；不猜缺失字段的值（缺失标 unknown）
```

## §2 上下文压缩（主线程只当路由）

| 原则 | 做法 | 反例 |
|------|------|------|
| 摘要 ≤200 字 | subagent 回复固定三段式：完成清单＋关键结论＋产物路径 | 回传整份报告原文 |
| 数据给路径不给内容 | 「结果在 /out/x.md 第 2 节」 | 把 5000 字表格贴进对话 |
| 下发传摘要不传原文 | 给 subagent 的上下文 = 结论级摘要（≤10 行） | 把主线程读过的全文塞给每个 subagent |
| 大输入先落盘再传路径 | 语料先写 /data/xxx 文件，prompt 只给路径＋行数 | prompt 内联大段数据 |
| 聚合读文件不读对话 | 主线程合并结果时读落盘产物，不凭对话回忆 | 靠各 subagent 当时的回复拼最终报告 |

量化线与自检：
- 单条 subagent 回复 >200 字即超标 → 主线程只取三段式部分，其余回一句「内容请补写进产物文件」
- 下发前自检：prompt 里最长的引用块是否超过 10 行？超过 → 换成路径＋摘要
- 主线程聚合前自检：本轮收到的对话总量是否超过全部产物文件大小的 10%？超过 → 压缩失守，回查各 prompt 的产出格式要素

给 subagent 的上下文摘要模板（≤10 行，只传结论＋指针）：
```
【已知结论】
1. 站点共 87 个接口，前缀 /api/v2，全部需鉴权（依据 /out/接口清单.md）
2. 其中 3 个接口已知返回 5xx（清单中标 ! 的行）
3. 你只负责 user 相关的 12 个：清单在 /data/user_api.txt
```
要点：结论落行、出处给路径；禁止把清单原文粘进 prompt。

## §3 幂等与断点（台账 + 锁）

台账格式（批任务启动时建 /out/台账.md 或 台账.jsonl）：
```
| 任务ID | 子任务 | 状态(pending/queued/running/done/failed/skipped/superseded) | 产物路径 | 开始 | 结束 | 备注(失败级别/降级原因) |
```

填好的示例两行：
```
| T1 | 提炼模块A接口 | done | /out/A_接口.md | 10:01 | 10:07 | — |
| T2 | 提炼模块B接口 | failed | — | 10:01 | 10:04 | L1超时×2，转切片 T2a/T2b |
```

规则与操作：

| 规则 | 做法 |
|------|------|
| 逐条更新 | 状态一变就改台账，不等批次结束 |
| 断点续跑 | 重启先读台账：done 跳过、failed 按 §4 处置、pending/queued 重发；**禁止从头重跑** |
| 幂等写入 | 产物先写 .tmp 再原子改名；或写入前查「产物已存在且非空 → 直接标 done」 |
| 锁粒度 | 数据锁 = 产物文件级（一个产物路径一把锁）；进程锁 = pid 文件/脚本名，启动前 `pgrep -f <脚本名>` 查重，重复先 pkill 清场确认计数归零再启 |
| 增量落盘 | 每处理 1 条 append 一行结果；每 N 条打一次进度日志（含已完成数/总数）；禁止攒到最后一次性写 |

启动前查重与清场（按序执行，任何一步不符就停）：
```
pgrep -f scan_all.py                     # 有输出 = 已有实例，禁止再启
pkill -9 -f scan_all.py                  # 仅确认要清场时执行
pgrep -f scan_all.py || echo clean       # 必须回 clean 才允许启动
```

## §4 结果聚合模式

| 模式 | 适用 | 做法 |
|------|------|------|
| 表格合并 | 各 subagent 产出同构表（同表头） | 脚本 concat：csv/jsonl 直接拼；md 去掉各家表头再拼；拼完全局排序、按主键去重 |
| 冲突检测 | 不同 subagent 对同一对象下了不同结论 | 合并时按对象 ID 分组；同对象多版本 → 加「冲突」列标出，触发仲裁（重查该对象或人工） |
| 交叉验证双评 | 高价值/高风险结论 | 同一输入发 2 个独立 subagent（同 prompt）；结论一致才采信，不一致 → 第 3 个仲裁或降级人工确认 |
| 抽样复核 | 量大但单条价值低 | 随机抽 5-10% 细读；错误率 >10% → 该批全查 |

聚合动作顺序（主线程固定走这五步）：读全部产物路径（只读不重跑）→ 合并 → 冲突标记 → 抽验/双评 → 输出三件套（完成清单/失败与跳过/待人工）。

同构 csv 合并可用一行命令（去各家表头再拼接，随后按主键排序去重）：
```
awk 'FNR==1 && NR!=1 {next} {print}' /out/part_*.csv > /out/合并.csv
sort -u -t, -k1,1 /out/合并.csv -o /out/合并.csv
```

## §5 常见翻车表（症状 → 病因 → 防法）

| 翻车 | 症状 | 病因 | 防法 |
|------|------|------|------|
| subagent 重复探索 | 回复里写「我先浏览了整个仓库结构」；耗时远超预期 | prompt 输入要素缺路径/格式/已知摘要 | 输入要素给绝对路径＋格式＋结论级上下文 |
| 写冲突 | 后完成的覆盖先完成的；diff 出现别的任务的内容 | 并行任务改同一文件且无归属 | 下发前按文件列写者清单，冲突文件合并归属单一 subagent |
| 静默失败 | 台账停在 running；产物文件不存在且无报错 | 完成标准不可验证 / 没要求落盘 | 完成标准写成可验证条件；验收第 1 步先清点产物 |
| 上下文溢出 | subagent 中途截断、回复只言片语、丢失早期指令 | 输入或回传内容过大 | §2 压缩：路径化＋摘要化；单任务过大先递归拆分（拓扑 §1） |
| 层间抢跑 | L1 任务拿到的是 L0 的半成品 | 没等上游落盘验收就发下一层 | DAG 分层下发：上游产物落盘验收后再发下游 |
| 口径不一 | 各 subagent 表头/文件名对不上，合不了 | 产出格式要素没写死到表头级 | 产出格式给表头与文件名示例，逐字对齐 |
| 假完成 | 回复 done，抽验发现内容是占位/编造 | 无交叉验证、无抽验 | 高价值结论双评；验收抽验不过全查（SKILL.md §三） |
| 双实例污染 | 结果文件出现重复行/交错乱序 | 同一脚本起两个实例 | 启动前 pgrep 查重；pid 锁；台账备注实例号 |
| 超时黑洞 | 台账停在 running 超均值 2 倍无进展 | 任务过大或进程卡死 | 套topology-selection.md §5 再拆分；后台批必须打进度日志 |
| 台账断更 | 长批在跑但进度日志久不动 | 进程静默死 | 查 pgrep 与产物文件 mtime；确认死了按断点续跑重启 |
