# orchestrator：多智能体编排

一句话流程：接任务 → 画 DAG 选拓扑 → 并行下发 subagent → 监控补位 → 聚合产物 → 集成验收。
本文件是路由层：短表命中哪行就开哪节，**禁止上来通读知识库**。

## 〇、先用 30 秒判断用不用本技能

| 判断 | 用 | 不用 |
|------|----|------|
| 子任务数 | ≥2 且相互独立（或可分层） | =1 |
| 单任务耗时 | 多数超过启动 subagent 的开销 | 都是秒级轻活 |
| 产物 | 可落盘、可核对 | 只需口头回一段话 |

三条全在「用」列 → 按短表走；任一落在「不用」→ 主线程直接做完，不硬拆。

| 场景 | 动作 | 开哪节 |

## 二、执行纪律

| # | 纪律 | 违反后果 |
|---|------|----------|
| 1 | subagent prompt 自包含五要素——目标（一句话）/ 输入（路径＋格式＋已知上下文摘要）/ 产出格式（落盘路径＋≤200 字摘要）/ 完成标准（可验证）/ 禁止事项 | 缺任一要素 → subagent 重复探索或假完成，烧 token 拖时间 |
| 2 | 产物落盘不靠对话回传：大内容写文件，主线程只收路径＋摘要 | 主线程上下文溢出，聚合阶段翻车 |
| 3 | 改同一文件必须串行归属：按文件/模块划给同一 subagent，或排队执行 | 并行写同一文件 → 互相覆盖 |
| 4 | 层间不抢跑：下一层必须等上一层产物落盘并验收后再下发 | 拿到半成品做出错结果 |
| 5 | 预估 >1 分钟的脚本（构建/测试/批处理/爬取）一律后台跑＋增量落盘（逐条写＋每 N 条打进度） | 前台阻塞干等；跑完才落盘＝中断全丢 |
| 6 | 单实例：启动前 pgrep 查重，发现重复先清场再启 | 双实例写同一结果文件，数据污染 |
| 7 | 独立子任务同一轮全部并行下发（默认 4-8 个，输入允许可 8-10＋） | 串行磨＝总耗时变成各任务之和 |
| 8 | 主线程只编排（拆分/下发/监控/合并/验收），不亲自做大块实现 | 主线程被占死，并行优势归零 |

例外（不拆直接自己做）：单文件小改、有严格依赖顺序的步骤、比启动 subagent 还便宜的轻活。

## 三、验收口径（集成检查怎么做）

全部 subagent 完成后，主线程按下表按序执行；任一步不过就定点修复，修复后从该步重走：

| 步骤 | 检查项 | 不过怎么办 |
|------|--------|-----------|
| 1 清点 | 对照台账逐个核对：承诺的产物文件存在且非空 | 缺产物 → 按拓扑选择.md §4 失败处置重下发该子任务 |
| 2 构建 | 跑一次整体构建/编译 | 挂了 → 按报错定位归属子任务，只对该范围下发修复任务 |
| 3 测试 | 先跑受影响部分，过了再全量 | 同上；修复任务禁止扩大改动范围 |
| 4 冲突 | 同文件曾被多个写者碰过的，diff 查覆盖痕迹 | 有覆盖 → 按台账时间戳恢复，该文件重做 |
| 5 抽验 | 每类产物抽 1 份细读；高价值结论交叉双评 | 抽验不过 → 该类产物全查 |

补充口径：降级产物（拓扑选择.md §4 级别 3）必须在台账注明「降级＋原因」，验收时单列；最终输出三件套（缺一不算完）：**完成项清单 / 失败或跳过项及原因 / 需要人工确认的点**。
