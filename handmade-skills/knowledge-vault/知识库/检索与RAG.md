# 检索与 RAG：三层路由与本地实现

## 三层检索

| 层 | 靠什么 | 适用（还记得什么） | 成本 | 失效场景 |
|----|--------|------------------|------|---------|
| 关键词层 | 文件名+全文搜索（grep / Ctrl+F） | 记得原词、术语、代码片段 | 零 | 忘词、同义改写 |
| 标签/链接层 | 标签过滤、MOC 顺链跳转 | 记得类目与主题，不记得细节 | 中（靠录入纪律） | 标签没起好、跨域问题 |
| 语义层 | embedding 向量近邻 | 只记得大意（「之前看过一篇讲切太碎会怎样的」） | 高（要建 RAG） | 黑话、超短笔记、索引滞后的一周新内容 |

选层顺序：先关键词（秒级）→ 不中再标签/链接（十秒级）→ 都不中才语义层，且先确认库里真有这条。三层都不中 → 该知识没录入，回录入流程，不是调检索参数。

obsidian 内对应：Ctrl+F 全文 / 标签面板+MOC / Smart Connections 类插件或外接脚本。

## 本地 RAG 最小实现

流水线：读 md → 切块 → 嵌入 → 入库；查询侧：问题嵌入 → 近邻 top-k → 拼上下文给模型。

```bash
pip install sentence-transformers chromadb   # 起步两件套
```

### 切块策略表

| 策略 | 切法 | 起点参数 | 适用 | 风险 |
|------|------|---------|------|------|
| 固定长度 | 按字符数等分 | 500 字/块 | 格式统一的技术文档 | 硬切断句 |
| 固定+重叠 | 等分且相邻块重叠 | 块 400 字，重叠 80（重叠 = 块长 15-20%） | 通用默认起步 | 存储与检索量增大 |
| 按标题 | markdown 标题为界 | `##` 二级标题成块，单块超 800 字再对半二分 | 结构良好的笔记库（原子笔记库天然适合） | 无标题文件整篇成块 |

中文分块注意：
- 按**字符数**切（`len(text)`），不按英文 token 数；中文 1 字 ≈ 1.5-2 token，按 token 切会把块切得过碎
- 切点优先落在句子边界：先按 `。！？\n\n` 分句，再贪心装袋到目标长度
- 每块前置上下文头：`文件名 > 一级标题 > 二级标题`，否则召回后不知出处

### 入库与查询骨架

```python
from chromadb import PersistentClient
from sentence_transformers import SentenceTransformer
m = SentenceTransformer("BAAI/bge-small-zh-v1.5")
col = PersistentClient("./vault_db").get_or_create_collection("notes")
col.add(ids=ids, documents=chunks, embeddings=m.encode(chunks).tolist())   # ingest
hits = col.query(query_embeddings=m.encode([q]).tolist(), n_results=5)     # query
```

### 增量更新

按文件 hash 判改动：新文件 → 入库；hash 变 → 先 `col.delete(ids=该文件旧块id)` 再入新块；未变 → 跳过。每周蒸馏后跑一次全量校验兜底。

### eval.jsonl 示例（一行一题，q=问题，a=正确笔记文件名）

```json
{"q": "切块切太碎有什么问题", "a": "重叠切块能保住跨块语义.md"}
{"q": "中文笔记按什么单位切块", "a": "中文分块要按字符数不按token.md"}
{"q": "向量库怎么选", "a": "个人库默认用chroma.md"}
```

题目来源：真实卡过的时刻（当场记下来），不要事后编造——编的问题测不出真实命中率。

## 选型两表

### embedding 选型表

| 档 | 模型例 | 维度 | 语种 | 部署 | 适用 |
|----|--------|------|------|------|------|
| 本地 CPU 轻量 | BAAI/bge-small-zh-v1.5 | 512 | 中 | sentence-transformers，CPU 秒级 | 全中文、千条以下个人库首选 |
| 本地标准 | BAAI/bge-m3 | 1024 | 多语种 | CPU 可跑但慢，GPU 快 | 中英混库、>2000 条 |
| 国内 API | 智谱 embedding-3 / 阿里 text-embedding-v3 | 2048 / 1024 | 中英 | 按量计费 | 不想维护本地、量大 |
| 海外 API | OpenAI text-embedding-3-small | 1536 | 多语种 | 需出境代理 | 已有账号、图省事 |

判据：全中文小库 → 第一档够用；出现「英文术语搜不到中文笔记」→ 升多语种档；**换模型必须全量重建向量库**（不同模型的向量不可混用）。

### 向量库速查

| 库 | 形态 | 适用 | 起步 |
|----|------|------|------|
| sqlite-vec | sqlite 扩展，单文件 | <1 万条、要随身带一个 .db、零运维 | `pip install sqlite-vec` |
| chromadb | 嵌入式，自带存储+元数据过滤 | 个人 RAG 默认档，支持 where 条件 | `pip install chromadb` |
| faiss | 纯向量索引，无存储无元数据 | >10 万条、追极致速度，元数据自己管 | `pip install faiss-cpu` |

判定：<1 万条个人库 chroma；只要一个单文件随库走 sqlite-vec；量级或延迟真撞墙才 faiss。

## 召回评估

### 自测法：固定问题集

建 `eval.jsonl`：20-30 个真实问题，每题人工标注正确笔记文件名。每次调参后跑同一问题集对比：

| 指标 | 定义 | 及格线 | 不及格先查 |
|------|------|--------|-----------|
| 命中率@5 | top-5 含正确笔记的题占比 | ≥80% | 切块策略、embedding 选型 |
| 首位率 | 正确笔记排第 1 的占比 | ≥50% | 排序：加 rerank 或提阈值 |
| 漏检率 | 正确笔记不在 top-5 的占比 | ≤20% | 切太碎、问题改写 |

日常漏检自测：每周抽 5 条「以前搜到过」的旧问题重问，命中低于 4 → 回上表查因。

### top-k 与阈值调法

| 症状 | 调整 |
|------|------|
| 相关块被挤出 top-k | k 从 5 → 8，上限 10（再多撑爆 prompt 且稀释信号） |
| 噪音块混入 | bge 系 cosine 阈值 0.30 起步，噪音多升 0.35-0.40；或保持 k、加 reranker 重排 |
| top-k 全来自同一篇 | 开 MMR（chroma 传参或 faiss 后处理去重）强制来源多样 |

调参顺序固定：先切块 → 再 k/阈值 → 最后才换模型；每步只动一个变量并记录 eval 结果。

## 常见翻车表

| 症状 | 根因 | 修法 |
|------|------|------|
| 检索到了但答非所问 | 块相关但内容不足 | 块前置「文件名>标题」上下文头；召回后拼同文件相邻块 |
| 切太碎，召回块读不出语境 | 块 <100 字 | 块长升 400-500、重叠 15-20%；<300 字短笔记不切整篇入块 |
| 笔记改了，检索仍出旧内容 | 向量未随源更新 | hash 增量重建；每周蒸馏后跑全量校验 |
| 中文问题搜不中英文库（或反之） | 单语 embedding | 换 bge-m3 多语种档并全量重建 |
| 问法稍变就完全不中 | 只靠向量单路 | 上混合检索：BM25 关键词+向量各召回一半再合并 |
| 短笔记检索质量差 | 超短文本向量不稳 | 短笔记按主题聚合成块再嵌入，或语义层只索引长文 |
| 越查越慢 | 全表扫 | 万条内属正常；超了 faiss 建索引或调 chroma hnsw 参数 |

## 何时放弃 RAG

库 <200 条且标签纪律在执行 → 关键词+标签层够用，RAG 是负资产（维护成本 > 收益）。语义层只在前两层真实失效（月均 ≥5 次「记得有但搜不到」）才上；上了之后前两层照常维护——语义层是兜底，不是替代。
