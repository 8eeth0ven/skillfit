# 笔记体系：录入、组织与蒸馏

## 原子笔记法

一条原子笔记 = 一个观点。判据：标题能写成一句完整判断句（如「重叠切块能保住跨块语义」）；写不成 → 装了不止一个观点，拆。

### 三件套模板（落盘即填，缺一不算录入完成）

```markdown
# <一句判断句标题，15-30 字>
<观点正文：2-5 行，用自己的话转述，禁止整段复制原文>

## 出处
- 来源：URL / 书名+页码 / 对话(日期,对象)

## 将来用途
- 检索词：将来我会搜的 2-3 个词
- 链接：[[相关笔记]] 1-3 条
- 标签：#动词/名词 1-3 个
```

三件套对应三个将来动作：

| 件 | 将来靠它做什么 | 缺失后果 |
|----|--------------|---------|
| 观点正文 | 被检索到后直接可用，不必回原文 | 找到了还得重读原文，等于白存 |
| 出处 | 证伪、引用、回溯 | 观点无法核实，逐渐不敢用 |
| 将来用途 | 关键词层+链接层+标签层的全部入口 | 三层检索同时失效 |

### 拆分判定

| 正文出现 | 动作 |
|---------|------|
| 「另外」「顺带」「同时」引出第二个观点 | 拆两条，互加双链 |
| 一个流程多个步骤 | 流程本身一条，每个可复用观点各起一条链接回流程 |
| 正例与反例 | 同一观点的两个证据面，并入同条，不拆 |
| 超过 300 字还没写完 | 大概率两个观点混装，重读拆分 |

## 链接组织

### 三者分工表

| 机制 | 管什么 | 不管什么 | 用法上限 |
|------|--------|---------|---------|
| 双链 `[[]]` | 这条与哪条观点相关（点对点关系） | 分类 | 每条 1-5 条，宁缺毋滥 |
| 标签 `#` | 这条属于什么可检索类目（一对多归集） | 具体关系 | 每条 1-3 个 |
| 文件夹 | 流转状态与来源域（收集箱/笔记/归档） | 主题分类 | ≤2 层；主题分类交给 MOC |

判定链：想归类 → 先看能否链接到已有主题页 → 不能再起标签 → 标签也不行才动文件夹。新建第 3 层目录前默认是错的。

### 标签生成法：动词+名词

标签格式 `#动词/名词`，描述「这条知识参与什么动作」：

| 知识内容 | 标签 | 错误示范 |
|---------|------|---------|
| embedding 维度选择经验 | #选型/embedding | #AI #技术 #向量 |
| obsidian 快捷键 | #操作/obsidian | #工具 #效率 |
| 周报模板 | #写作/周报 | #工作 #模板 |
| 某报错成因 | #排查/切块 | #bug |

生成步骤：问「我将来做什么动作时会需要它」→ 动词定档 → 查重：已有同义标签则复用不新增。动词表受控（≤10 个，如 选型/操作/写作/排查/复习），名词域开放。

治理（每月蒸馏时）：合并同义标签；删仅 1 条引用且 4 周无新增的标签；动词表超 10 个就收编归并。

## 命名规范

| 型 | 格式 | 适用场景 | 例 |
|----|------|---------|-----|
| 主题型 | `<判断句>.md` | 概念/观点笔记，库内主力默认 | 重叠切块能保住跨块语义.md |
| 日期型 | `YYYY-MM-DD-<事由>.md` | 日志、会议、周报、一次性事件 | 2026-10-10-周清.md |
| 序号型 | `<NN>-<步骤名>.md` | 教程、系列、有严格顺序的流程 | 03-切块入库.md |

规则：全库默认主题型，日期/序号只在场景明确时用；同一主题禁止混型（不并存「RAG入门.md」与「2026-09-01-RAG.md」）；文件名避开 `/` `[]` `#` `|`。

## 蒸馏流程

四步循环，每周一次，每次 30 分钟封顶。

| 步 | 输入 | 动作 | 完成判定 |
|----|------|------|---------|
| ① 收集箱清空 | 收集箱全部条目 | 逐条三选一：扩成原子笔记 / 合并进已有笔记 / 删 | 条数 = 0 |
| ② 处理新笔记 | 本周新建笔记 | 补齐三件套（重点补「将来用途」）；与旧笔记互链 | `[待补出处]` 存量 = 0 |
| ③ 维护主题页 | 本周高频访问主题 | 新笔记挂进对应 MOC；无 MOC 且同主题链接 ≥5 条 → 新建 MOC | 每条新笔记至少有一个入口 |
| ④ 索引与删旧 | 全库 | 更新总索引；4 周零引用移 `9-归档/`；合并同义标签 | 活跃区无死链 |

判定细则：
- 删的勇气测试：「将来想要却没了，最坏损失是什么」——重搜 5 分钟能找回 → 删；找不回 → 归档
- MOC（内容地图）：一主题一页，只放链接+一句话导语；链接超 30 条拆子 MOC
- 蒸馏产出的是结构变化（合并/归档/挂链），不是新文章

## obsidian 实操速查

### 文件夹结构（2 层封顶）

```
vault/
├── 0-收集箱/    # 未处理，只进蒸馏
├── 1-笔记/      # 原子笔记，主题型命名
├── 2-项目/      # 按项目聚合的过程文件
├── 3-索引/      # MOC 与总索引
└── 9-归档/      # 4 周零引用，只进不出
```

设置两处：设置→文件与链接→新链接格式选「相对路径」；核心插件开「日记」「模板」「标签面板」；社区插件装「Dataview」。

### dataview 三例（直接贴入笔记）

最近 7 天修改的笔记（周清入口）：

```dataview
LIST file.mtime
FROM "1-笔记"
WHERE file.mtime >= date(today) - dur(7 days)
SORT file.mtime DESC
```

按标签收集某主题全部条目（写 MOC 用）：

```dataview
LIST
FROM #选型/embedding
SORT file.ctime ASC
```

收集箱积压监控（表中出现条目 = 超期 2 天，该蒸馏）：

```dataview
TABLE file.ctime AS "进入时间"
FROM "0-收集箱"
WHERE file.ctime <= date(today) - dur(2 days)
SORT file.ctime ASC
```

### 死链检测

- 图谱法：关系图谱→筛选→勾「孤立文件」；逐文件看右侧「出链」面板的未解析链接
- 脚本法（库根目录跑，输出死链候选）：

```bash
grep -rhoE '\[\[[^]|#^]]+' --include='*.md' . | sed 's/^\[\[//' | sort -u > /tmp/links.txt
fd -e md -x basename {} .md | sort -u > /tmp/files.txt
comm -23 /tmp/links.txt /tmp/files.txt
```

## 防烂尾

### 每周蒸馏清单（30 分钟，按序打勾）

| # | 项 | 量化线 |
|---|-----|--------|
| 1 | 收集箱清零 | 条数 = 0 |
| 2 | 补三件套 | `[待补]` 存量 = 0 |
| 3 | 新笔记挂 MOC | 本周新增 100% 有入口 |
| 4 | 零引用降级 | 4 周未动条目全部移 `9-归档/` |
| 5 | 标签治理 | 动词表 ≤10；无单人标签 |
| 6 | 死链清零 | 死链数 = 0 |
| 7 | 记周清日志（日期型命名） | ≤3 行：处理量/删除量/待办 |

### 烂尾信号与急救

| 信号 | 判断 | 急救 |
|------|------|------|
| 连续 2 周没开库 | 录入成本 > 收益 | 砍流程：只留三件套模板，双链/标签降为可选 |
| 收集箱常年 >50 | 蒸馏频率不够 | 一次性删掉 2 周前全部条目（敢删才敢存） |
| 找东西永远全文搜索 | 组织层失效 | 停录 1 周，专补存量笔记的「将来用途」件 |
| 同步冲突后弃库 | 工具负担过重 | 退回纯 md 目录 + grep，卸载同步与重型插件 |
