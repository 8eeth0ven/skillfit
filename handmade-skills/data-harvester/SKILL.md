# data-harvester：公开数据采集

铁律：**只采公开数据**（不登录就能看到的），接口优先于渲染，增量落盘优于一次跑完。本文件只做路由，细节全在 `知识库/` 按需展开，禁止通读。

## 合规边界（先于一切技术）

| 红线 | 工程化处理 |
|------|-----------|
| 只采公开数据 | 需登录/Cookie 会话才可见的数据一律不碰，除非用户明确声明拥有该账号且授权 |
| robots.txt | 进站第一步 `curl -s https://<host>/robots.txt`，命中 Disallow 前缀的路径跳过并记台账「robots 禁」 |
| ToS 禁爬 | 页面/ToS 明示禁止自动采集 → 停，告知用户，不找绕法 |
| 速率 | 默认 ≥1.5s 间隔起步；目标站是生产业务时再放宽，禁止打挂对方 |
| 个人敏感信息 | 身份证/手机号/住址等，即使公开页面出现也只采任务必需字段，产物不外传 |

## 必读短表（场景 | 动作 | 开哪节）

| 场景 | 动作 | 开哪节 |
|------|------|--------|
| 目标站有前端 SPA | 先抽 JS 接口再决定要不要渲染 | 接口优先法.md §1–§2 |
| curl 页面直接有数据 | 裸 HTTP 走接口法，不上浏览器 | 接口优先法.md §2 |
| 数据在页面里但 curl 拿不到 | 查初始状态 JSON，再考虑渲染 | 渲染与反爬.md §1 |
| 翻页不知道何时停 | 分页三型对号入座 + 终止判定 | 接口优先法.md §3 |
| 列表拿完要详情/附件 | 三段式抓取，队列驱动 | 接口优先法.md §4 |
| 接口带 sign/token/时间戳 | 静态分析签名参数 | 接口优先法.md §5 |
| 接口是 GraphQL | 批量 alias + 翻页 | 接口优先法.md §6 |
| 滚动加载/虚拟列表 | 先拦接口，拦截不到才模拟滚动 | 渲染与反爬.md §3 |
| 403/429/超时/空内容 | 按失败分类表处置，不盲目重试 | 渲染与反爬.md §6 |
| Cloudflare 5s 盾/验证码 | 盾重试 2 次即放弃；验证码=停止信号 | 渲染与反爬.md §4 |
| 只要新增/变更数据 | content hash + etag/last-modified | 渲染与反爬.md §5 |
| 任务中断要续跑 | 按产物约定的 state.json 恢复 | 本文件「产物约定」 |
| 要登录才能看 | 停，引用合规边界表向用户确认 | 本文件「合规边界」 |
| 不确定开哪节 | 开 知识库/明细目录.md | 明细目录.md |

## 流程总览（顺序不可换）

1. **定范围**：目标 URL → robots.txt → 公开性判定（要不要登录）→ 明确要采的字段
2. **探接口**：curl 首页 → 有 JS bundle 就抽 API（§1）→ network 对照确认数据接口（§2）
3. **选通道**：接口能通走 HTTP；不通查初始状态 JSON；都没有才上 Playwright（渲染与反爬 §1）
4. **跑增量**：分页终止判定（§3）→ 逐条写 jsonl → 每 50 条存断点
5. **收尾**：台账对账（计划数 vs 实采数）→ 失败项归因 → 产物三件套齐

## 执行纪律（违反任何一条，本次采集作废）

1. **增量落盘**：每采 1 条立刻写 jsonl，每 50 条 `f.flush()` + 更新 state.json；禁止攒内存跑完再写。
2. **单实例**：启动前 `pgrep -f <脚本名>` 查重，脚本内用 `fcntl.flock` 抢 `run.lock`，抢不到直接退出。
3. **失败退避**：超时/5xx 重试 ≤3 次，间隔 2s→8s→30s 指数退避；429 读 `Retry-After` 头等待；连续 5 次失败熔断本次任务。
4. **UA/速率分寸**：UA 用真实浏览器串并保持全程一致；默认 sleep 1.5–3s 随机抖动；对方明显限流就降速，不是换 IP 硬冲。
5. **公开数据 only**：过程中拿到登录态 Cookie/会话数据不使用、不保存；发现接口越权返回非公开数据 → 停采，记录并告知用户。
6. **对抗有上限**：盾/验证码/风控是明确停止信号，放弃阈值见渲染与反爬 §4；不调代理池、不破解验证码。

## 产物约定（固定三件套 + 断点）

```
<任务目录>/
├── data/items.jsonl   # 数据：每行 1 个 JSON 对象，UTF-8，ensure_ascii=False
├── 台账.md            # 对账：计划 URL 数 / 成功 / 失败 / 跳过(robots|盾|登录墙) / 归因
├── state.json         # 断点：续跑只依赖此文件
└── logs/run.log       # 运行日志：时间+URL+状态码+耗时，逐行追加
```

state.json 最小格式（三型分页通用）：

```json
{
  "seed": "https://example.com/list",
  "pager": {"type": "offset", "last_offset": 400, "limit": 20},
  "done_urls": ["<url 的 sha256 前 16 位>", "..."],
  "finished": false,
  "updated_at": "2026-10-10T12:00:00+08:00"
}
```

续跑规则：读 state.json → 跳过 `done_urls` → 从 `last_offset`/`cursor` 继续写同一 items.jsonl → 全部完成置 `finished: true`。

台账.md 最小表（每行一次采集决策，含失败）：

```markdown
| URL/批次 | 状态 | 归因 | 时间 |
|----------|------|------|------|
| /api/items?offset=0–400 | 成功 400 条 | — | 10-10 12:00 |
| /api/items?offset=420 | 跳过 | 429 降速后仍拦，熔断 | 10-10 12:40 |
| /api/user/private | 停 | 登录墙，非公开数据 | 10-10 12:41 |
```

## 速率速查

| 对象 | 默认 | 放宽条件 |
|------|------|---------|
| 普通 Web/API | 1.5–3s 随机抖动 | 明确静态 CDN/OSS 附件可到 0.5s |
| 429 后 | 间隔 ×3 | 收到 2xx 正常响应后维持一档慢速 |
| 同 host 并发 | 1（串行） | 任务声明允许且未触发限流时 ≤2 |
