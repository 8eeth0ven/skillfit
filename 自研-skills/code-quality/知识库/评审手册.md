# 评审手册

> 用法：只开命中的节。§1 定顺序 → §2 定级别 → §4 逐类找问题 → §3/§5 出产物；大数据量/并发代码加 §6；性能问题走 §7；扯不清走 §8。

## §1 评审优先级序：正确性 > 安全 > 接口 > 可读性 > 风格

按序扫，高层级没清完不看低层级；风格问题一律最后说或直接交给 lint。

| 优先级 | 看什么 | 典型命中 | 什么时候可以让位 |
|---|---|---|---|
| 1 正确性 | 逻辑会不会错：边界、空值、异常路径、状态一致性 | 差一错误、除零、异常时留下脏状态 | 永不让位 |
| 2 安全 | 输入可信吗：注入、越权、敏感信息 | SQL 拼接、密钥进日志、路径穿越 | 永不让位 |
| 3 接口 | 契约破坏吗：签名、出入参、错误码、兼容性 | 返回结构变了没升级版本、抛的异常类型变了 | 有明确废弃公告 + 过渡期 |
| 4 可读性 | 半年后自己看得懂吗：命名、函数长度、重复 | 一个函数 200 行、三处复制粘贴 | 紧急修复可先合，事后补 |
| 5 风格 | 格式统一吗：缩进、引号、import 顺序 | 单双引号混用 | 全部移交 lint/formatter，人只管补 lint 配置 |

动作序列（进 diff 后按序执行，对应 SKILL.md 纪律 1）：

| 步 | 动作 |
|---|---|
| 1 | 读 PR 描述/commit message，用一句话说清本次改动意图 |
| 2 | 先看对外接口：签名、出入参、错误码、序列化格式变了没 |
| 3 | 按优先级 1→5 扫实现代码，命中 §4 问句即记下行号 |
| 4 | 大数据量/并发/异步代码追加过一遍 §6 清单 |
| 5 | 全部意见按 §2 定级，落 §3 意见表 |
| 6 | 按 §5 模板逐条写 comment，最后给回执段 |

## §2 分级意见口径表

| 级别 | 判定标准（满足其一） | 行内标注格式 | 作者处理方式 |
|---|---|---|---|
| 必须改 | 会让程序出错/不安全/破坏对外契约，不修不能合 | `[必须改] 位置 一句话问题` | 改完逐条回复；改不了须说明理由并经评审者同意降级 |
| 建议 | 不改也对，改了更好：重复代码、命名含糊、手写轮子 | `[建议] 位置 一句话问题` | 可接受可拒绝，拒绝回一句理由即可 |
| 疑问 | 没看懂或缺上下文，不一定是问题 | `[疑问] 位置 一句话问题` | 作者补说明；确认非问题后标「已澄清」关闭 |

两条禁令：
- 禁把个人风格偏好升成「必须改」（偏好 ≠ 缺陷）。
- 禁把会崩的问题降成「建议」（有清楚复现路径的一律必须改）。

## §3 评审意见表（评审产物，列固定）

| 级别 | 位置 | 问题 | 依据问句 | 建议改法 |
|---|---|---|---|---|
| 必须改 | `order.py:47` `calc_refund()` | 金额为 0 时除零崩溃 | 边界-1 | 入口先判 `if amount <= 0: raise InvalidAmount` |
| 疑问 | `order.py:63` | 为什么这里 sleep(500)？ | 竞态-1 | 请补注释或删除 |
| 建议 | `order.py:88` | 三处重复拼同一个串 | 可读-2 | 提取 `_build_msg()` |

规则：一行一个点；位置精确到函数或行；依据问句填 §4 编号；建议改法给方向，不贴大段代码。

## §4 常见问题模式表（检查问句，逐条问，答案要能落到是/否）

| 编号 | 模式 | 检查问句 |
|---|---|---|
| 空值-1 | 空指针/None | 这个函数每条返回分支各返回什么？调用方对每种返回都处理了吗？ |
| 空值-2 | 空指针/None | `d[k]`、`list[0]`、`obj.field` 这类取值前，判过空和存在吗？ |
| 边界-1 | 边界 | 循环第一轮和最后一轮，关键变量各是什么值？手推一遍了吗？ |
| 边界-2 | 边界 | 空集合、单元素集合进来，这条路径走得通吗？ |
| 边界-3 | 边界 | 这个 `<` 改成 `<=` 结果会变吗？会变的话写清为什么选现在这个 |
| 泄漏-1 | 资源泄漏 | 每个提前 return / 抛异常的路径上，打开的文件/连接都关了吗？ |
| 泄漏-2 | 资源泄漏 | 用了 `with` / `try-finally` / `defer` 吗？裸写 open/close 的一律追问 |
| 竞态-1 | 竞态 | 这段「先查再改」（check-then-act）中间插入另一个请求会怎样？ |
| 竞态-2 | 竞态 | 这个共享变量会被谁并发写？有锁/原子操作/CAS 保护吗？ |
| 竞态-3 | 竞态 | 双重检查锁的字段有 volatile/内存屏障吗？ |
| 吞错-1 | 错误吞掉 | 每个 `except`/`catch` 块：异常记日志了吗？带堆栈吗？之后继续跑还是重抛？ |
| 吞错-2 | 错误吞掉 | 用返回 None/错误码表示失败的地方，每个调用方都检查了吗？ |
| 魔法-1 | 魔法数 | 裸数字/裸字符串（86400、0x1F、"/tmp/x"）各是什么含义？有名字吗？ |
| 注入-1 | 注入 | 拼 SQL/命令/路径的字符串里含用户输入吗？参数化了吗？ |
| 泄密-1 | 敏感信息 | 日志/报错信息里出现密码、token、身份证号了吗？ |
| 超时-1 | 外部调用 | 调外部服务/DB 设超时了吗？没设的话对端挂了会等多久、堆多少请求？ |
| 重试-1 | 外部调用 | 重试有次数上限和退避吗？重试失败后的副作用（重复下单/重复发信）处理了吗？ |
| 日志-1 | 可观测 | 关键分支有日志吗？带上下文 id（订单号/traceId）吗？还是只打了 "error"？ |
| 兼容-1 | 接口 | 新旧字段/格式并存时，还在跑的老消费方会挂吗？ |
| 可读-1 | 可读性 | 函数超过一屏/嵌套超过三层吗？ |
| 可读-2 | 可读性 | 同一段逻辑出现两次以上吗？ |

用法：不逐条贴进 comment；命中哪条记到意见表「依据问句」列。

## §5 评审 comment 模板（肯定-问题-建议-回执四段，缺段重写）

```text
【肯定】order.py:12 的金额全用 Decimal，避开了浮点误差，这个处理对。
【问题】[必须改] order.py:47 calc_refund 金额为 0 时除零（依据：边界-1）。
【建议】[建议] order.py:88 三处重复拼串可提取 _build_msg()（依据：可读-2）。
【回执】请按级别逐条回复处理结果；对「必须改」有异议直接在本条下讨论，不许静默降级。
```

规则：肯定段必须具体到行与原因，「写得不错」四个字不算；问题段必带 级别+位置+依据；一段一条，不混放。

## §6 大数据量/并发代码专项检查清单（在 §4 之上追加）

大数据量：

| 编号 | 检查问句 |
|---|---|
| 大-1 | 这段一次把多少数据装进内存？百万行进来会 OOM 吗？有分页/流式吗？ |
| 大-2 | 循环里查库/调外部接口吗？是 N+1 吗？能改批量吗？ |
| 大-3 | 这个全表排序/全量扫描，索引撑得住吗？EXPLAIN 贴过吗？ |
| 大-4 | 同一个大对象被序列化/深拷贝几次？能改引用或增量吗？ |
| 大-5 | 没写 LIMIT/分页的查询，说得出现实数据量下的合理上限吗？ |

并发/异步：

| 编号 | 检查问句 |
|---|---|
| 并-1 | 复合操作（先 get 再 put / 先查再更新）整体加锁了吗？单点原子够吗？ |
| 并-2 | 锁住的区间里有 IO/外部调用这类慢操作吗？能不能挪出锁外？ |
| 并-3 | 会出现两把锁交叉等待吗？全局加锁顺序统一吗？ |
| 并-4 | 异步任务抛的异常有人接吗？Future/Promise 的异常被 get 了吗？ |
| 并-5 | 这个操作并发执行两次，结果还一样吗（幂等）？重复请求会重复扣款/重复发消息吗？ |
| 并-6 | 线程池/协程池的大小和队列打满策略（拒绝/阻塞/丢弃）写明了吗？ |

## §7 性能慢的定位顺序（纪律 4「先测量再优化」的落地动作）

| 序 | 动作 | 禁止 |
|---|---|---|
| 1 | 定指标与基线：耗时/内存/QPS，写清数据来源（命令、数据量、环境） | 空说「感觉慢」 |
| 2 | 分段打点或 profiler 找出最慢一段 | 凭直觉猜瓶颈 |
| 3 | 只改最慢一段，一次一个变量 | 一次改三处再一起测 |
| 4 | 同环境同数据量复测，前后数据落 SKILL.md 产物 4 对比表 | 只报喜不报忧（变慢也要记） |

## §8 三轮未决升级路径

| 轮次 | 双方做什么 | 还没决就进下一轮 |
|---|---|---|
| 第 1 轮 | 评审者给 级别+依据问句；作者回证据（复现步骤/文档/数据）或直接改 | 第 2 轮：双方各补一个具体反例（能跑的步骤或 ≤8 行代码片段） |
| 第 2 轮 | 交换反例后仍各执一词 | 第 3 轮：写「分歧单」＝ 争点一句话 + 双方论据各 ≤3 条 |
| 第 3 轮 | 提交第三人（模块 owner/技术负责人）持分歧单裁决 | 裁决即终审：结论写回意见表，本轮不再开新轮 |

规则：三轮内只认证据（复现步骤、数据、文档链接），「我觉得」不算论据；任何一方开始重复已说过的论据，视为无新证据，直接进下一轮。
