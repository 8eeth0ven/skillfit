# 测试与重构

> 用法：只开命中的节。写测试走 §1→§2→§3→§4；重构走 §5，动手前先确认有测试兜底；没测试的遗留代码先 §6；欠账记 §7。

## §1 测试金字塔速查

| 层级 | 测什么 | 目标配比 | 单次运行 | 失败定位 | 维护成本 |
|---|---|---|---|---|---|
| 单元 | 单个函数/类内部逻辑，依赖全 mock | ~70% | 毫秒级 | 秒级，直接指到函数 | 低 |
| 集成 | 模块拼装：真 DB/缓存/消息队列 | ~20% | 秒级 | 分钟级，跨模块排查 | 中 |
| E2E | 用户流程整链路（UI/接口全真） | ~10% | 分钟级 | 小时级，全链路排查 | 高 |

规则：
- 修 bug 的回归测试放在能复现该 bug 的最低层级；只有完整用户路径才能复现的才上 E2E。
- 出现倒金字塔（E2E 最多）＝ 病态：先补单元层，再谈新功能测试。
- 一次提交新增的测试，60 秒内必须能全部跑完一遍，否则降层级。

## §2 好测试的判定表（F.I.R.S. + AAA）

| 判定 | 检查问句 | 不过怎么办 |
|---|---|---|
| 快 | 这个测试跑一次超过 100ms 了吗？ | 拆掉慢依赖：换 mock 或降到集成层 |
| 独立 | 单独跑、乱序跑、并行跑，结果都一样吗？ | 清掉共享状态：固定文件、全局变量、共用端口 |
| 可重复 | 换台机器、明天再跑，结果一样吗？ | 干掉对 时间/随机数/网络 的裸依赖，改成注入固定值 |
| 自验证 | 断言写了期望的具体值吗？还是只「没抛错就算过」？ | 改成期望值与实际值直接对比，并给足失败信息 |
| AAA | Arrange/Act/Assert 三段分得开吗？ | 一段一职责；多个互不相关的 Assert 拆成多个用例 |

命名口径：`test_<被测>_<场景>_<期望>`，如 `test_refund_zero_amount_raises`；只看名字就能知道失败原因，不用点开实现。

AAA 结构示例（三段各司其职，逐行对应）：

```python
def test_refund_zero_amount_raises():
    order = Order(amount=0)              # Arrange：备好被测对象与输入
    with pytest.raises(InvalidAmount):   # Act + Assert：动一下并当场断言
        order.refund()
```

反例（不自验证，禁止）：只调用 `order.refund()` 不断言、或断言写成 `assert result is not None`。

## §3 边界值选择法

对每个输入按下表取值，每个取值生成一条用例：

| 取值 | 检查问句 | 例（数量/金额/字符串） |
|---|---|---|
| 0 | 零值过得了入口检查吗？ | qty=0、amount=0、`""` |
| 1 | 最小正常值完整走得通吗？ | qty=1、amount=0.01、"a" |
| n | 常规量级结果对吗？ | qty=100 |
| 空 | null/None/[]/{} 进来是什么行为？会崩吗？ | items=[] |
| 非法 | 类型错/格式错/负数被拦下还是穿透？ | qty=-1、amount="abc"、email="@" |
| 极大 | 溢出/超长/OOM 在哪一步发生？ | 2^31、10MB 字符串、1e6 条列表 |

配比口径：边界与异常用例 ≥ 正常路径用例的 2 倍；每个对外函数至少覆盖 0/空/非法 各一条。

TDD 循环（每轮 ≤10 分钟，纪律对应 SKILL.md 纪律 2）：

```text
1. 挑一条未满足的边界写测试 → 跑 → 确认红（失败原因必须是断言失败，不是环境报错）
2. 写最小实现让它变绿（禁止顺手实现下一条）
3. 绿后重构去重复 → 全量测试仍绿 → 提交，回到 1
```

## §4 mock 分寸表

| 依赖类型 | mock 吗 | 理由 |
|---|---|---|
| 纯函数/工具类 | 不 mock，直接用 | 快且稳定，mock 反而测不到真逻辑 |
| 数据库/缓存 | 单元层 mock；集成层用真件/容器 | 单元要快，集成要真 |
| 第三方 HTTP API | mock（录好固定响应） | 外部不可控、慢、有限流 |
| 时间/随机数 | 必 mock（注入 clock/seed） | 不 mock 就不可重复，违反 §2 |
| 文件系统/网络 | 单元层 mock；集成层真件 | 同数据库 |
| 同仓库被调模块 | 优先不 mock，直接测组合 | mock 自己的代码＝ 测不到接缝 bug |

分寸线：
- mock 数量超过被测代码直接依赖总数的一半 → 先怀疑测的层级选错了。
- 依赖方接口一改、测试批量挂 → 说明 mock 到了不该 mock 的内部细节，退到公开接口。

## §5 重构手法速查（一次提交一个手法；每步后全量测试必须绿）

| 手法 | 什么时候用 | 一行示例 |
|---|---|---|
| 提取函数 | 一段代码需要注释才看得懂 | 「# 算折扣」那段 → 提成 `calc_discount(items)` |
| 内联函数 | 函数体比函数名还短 | `def is_adult(a): return a >= 18` → 调用处直接写 `age >= 18` |
| 搬移函数 | 函数用的数据几乎全在另一个模块 | `order.total_with_tax()` → `pricing.total(order)` |
| 卫语句 | 嵌套 if 超过两层 | `if not user: return None` 提前退出，替代整段包裹 |
| 替换条件式 | 同一套 switch/if 散落多处 | 按 type 分发改多态/查表：`handlers[event.type]()` |

提交序列模板（每条提交信息写明手法 + 声明行为不变）：

```text
refactor: 提取 calc_discount（纯移动，行为不变）
refactor: 卫语句化 process_order（行为不变，测试全绿）
feat: 折扣支持满减（改行为，与重构分开提交）
```

红线：改行为和改结构严格分开提交；没有测试覆盖的部分先补 §6 再动。

## §6 遗留代码加测试的接缝法

接缝 ＝ 不改外部行为就能替换内部依赖的位置。按优先级找：

| 优先级 | 接缝类型 | 做法 |
|---|---|---|
| 1 | 依赖注入点 | 构造函数/参数把 DB、时钟、发信器传进来，测试传假件 |
| 2 | 子类覆写 | 测试里继承被测类，覆写 `send_email()`/`now()` 等外部动作 |
| 3 | 抽接口层 | 把直连的外部调用包成接口；生产注册真件，测试注册假件 |
| 4 | 特性开关（最后手段） | 在副作用分支外加开关，测试环境关掉外部调用 |

步骤（每步跑一次现有测试）：

```text
1. 先写特征测试钉死当前行为（哪怕行为本身是错的，先记录再改）
2. 找到接缝插入假件，让被测代码可离线运行
3. 特征测试绿 → 按 §5 小步重构 → 每步全绿才提交
```

红线：禁止「看不懂就先重写」；先钉行为，再动结构。

## §7 技术债记录模板

一条一行落表（放仓库 `docs/tech-debt.md` 或任务目录）：

| 字段 | 填什么 | 例 |
|---|---|---|
| 编号 | TD-日期-序号 | TD-20261010-01 |
| 位置 | 文件:函数 / 模块 | pay/callback.py:process |
| 现状 | 现在怎么凑合的 | 回调未验签，靠 IP 白名单挡 |
| 后果 | 不还的具体代价 | 白名单漏配即可伪造支付成功 |
| 触发条件 | 什么情况必须还 | 接入第二个支付渠道之前 |
| 预估 | 还债动作 + 粗工作量 | 验签中间件，约 1 人日 |

规则：只记「不还会付出具体代价」的债；风格类不满不进表；每次发版前过一遍触发条件，命中即立任务还债。
