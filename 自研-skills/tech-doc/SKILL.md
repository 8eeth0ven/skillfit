# tech-doc 工程文档

## 定位

管工程文档的结构、排版、防腐；不管文字风格（那是"降AI味"的领域，两者可叠加）。核心主张：文档是给读者省时间的工具，不是给作者表功的展板。每个字都要经得起"读者为什么要读这一行"的追问。

## 读者三态（动笔前先选定）

| 读者态 | 他要什么 | 文档重心 |
|--------|---------|---------|
| 使用者 | 5 分钟跑起来 | 安装步骤、最小示例、报错对照表 |
| 维护者 | 改代码不踩坑 | 架构图、依赖方向、决策记录 |
| 评审者 | 判断要不要用 | 是什么/不做什么、对比、许可证、活跃度 |

一篇文档只服务一个主读者，其他读者放折叠或附录。三态都想讨好的文档，三态都服务不好。

## 必读短表（先路由，再动笔）

| 场景 | 动作 | 开哪节 |
|------|------|--------|
| 从零写 README | 先过五问定骨架再动笔 | `知识库/README五问.md` 全篇 |
| 改旧 README（没人看/重复提问多） | 五问逐问体检，缺哪问补哪问 | `知识库/README五问.md` §体检清单 |
| 写 API 文档 | endpoint 总表起步，逐接口套模板 | `知识库/API与架构文档.md` §API 文档模板 |
| 写架构文档 | 组件图→数据流→依赖→故障域，四件缺一不可 | `知识库/API与架构文档.md` §架构文档模板 |
| 记一次选型/技术决策 | ADR 四段式，一次决策一篇 | `知识库/API与架构文档.md` §ADR |

## 执行纪律（动笔前过一遍，交稿前再过一遍）

| # | 纪律 | 判定标准 |
|---|------|---------|
| 1 | 先想读者 | 一句话说出主读者是三态中的哪种；说不出 → 不动笔 |
| 2 | 结论先行 | 每节首句即结论；读者只读每节第一句也能带走全文骨架 |
| 3 | 每段一个任务 | 一段只干一件事（定义/步骤/对比/示例）；第二件事另起段 |
| 4 | 表格优先于长段落 | 并列项 ≥3 且可枚举 → 表格；顺序动作 → 编号步骤；只有叙述推理才用段落 |
| 5 | 时间精确到年月日 | 快照/版本/新闻禁止"最近、目前、最新"；精度按时间精度场景表选 |
| 6 | 数字必须可验证 | 性能/QPS/star 等每个数字配来源或复现命令；配不上 → 删数字 |

## 常见病灶速查（交稿前扫一遍）

| 病灶 | 典型表现 | 对应解法 |
|------|---------|---------|
| 形容词定义 | "强大优雅的现代工具" | 能力动词化 + 不做什么边界句 |
| 三态通吃 | 一篇既想招新用户又想指导重构 | 选主读者，其余进 details 折叠 |
| 结论沉底 | 关键结论埋在第五段 | 每节首句给结论 |
| 步骤叙述化 | 安装过程写成一段散文 | 编号步骤 + 可复制代码块 |
| 永远现在时 | "目前支持""最近新增" | 换 ISO 日期，按时间精度表选档 |
| 示例断头 | curl 里用省略号截参数 | 占位符全量、复制即执行 |
| 数字裸奔 | "性能提升显著" | 写基线数字与复现命令，写不出就删 |
| 报错无处查 | 出错只能翻源码 | 症状/原因/处理三列对照表 |

## 产物约定

| 项 | 约定 |
|----|------|
| 文件名 | README.md、CHANGELOG.md、docs/api.md、docs/architecture.md、docs/adr/NNN-短横线标题.md；全小写 |
| 代码块 | 每块必标语言（bash/json/mermaid/text）；输出块标 text 并注明"预期输出" |
| 示例可用性 | curl/命令必须可复制执行；占位符用尖括号 `<api-key>`，上下文说明替换来源；禁止省略号截断 |
| 日期格式 | 一律 ISO `YYYY-MM-DD`；引用数据的句子写"截至 YYYY-MM-DD" |
| 交付形态 | 新文档给整文件；改文档给 diff 说明 + 落盘路径；模板给骨架，不编造假数据 |
| 交稿自检 | 过对应知识库末尾的体检清单，逐项打勾后才算完成 |

## 路由规则

1. 本文件是唯一必读；知识库按需展开：只开命中篇的命中节，禁止通读知识库。
2. 命中多篇（如架构文档内含 API 节）→ 主类型开全篇，副类型只开模板节。
3. 知识库未覆盖的文档类型（需求文档、测试用例、专利交底）→ 只套执行纪律与产物约定，不硬套模板。
4. 与"降AI味"叠加：先用本 skill 定结构与排版，再用降AI味过文字层；结构规则不被文字层规则覆盖。

## 不触发边界

- 纯文字润色、去 AI 味 → "降AI味·反向法则" skill，本 skill 不介入。
- 学术论文、文学作品、营销文案 → 两者都不管，按需求单独处理。
