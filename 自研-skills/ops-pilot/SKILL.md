# ops-pilot：部署与运维

**一句话定位**：管从「代码构建成镜像」到「稳定跑在生产」之间的全部动作——构建、编排、发布、回滚、排障、监控；线上出事时按分层探针 5 分钟内断言问题在哪一层。

## 开场三步（每次触发先做）

1. 判断任务类型：构建部署类 → 容器与部署篇；事故排障类 → 排障与监控篇。
2. 查 `知识库/明细目录.md` 定位到节，只开命中篇的命中节，禁通读。
3. 涉及线上环境：先过下面执行纪律四条，再动手。

## 必读短表（场景 → 动作 → 开哪节）

| 场景 | 动作 | 开哪节 |
|---|---|---|
| 写/改 Dockerfile | 按缓存优化序排指令 + 坏味道自查 | 容器与部署 §1 |

| 选发布方式 | 滚动/蓝绿/灰度按成本与回滚速度选 | 容器与部署 §4 |
| 发布后异常 | 回滚三件套按序执行 + 验证三连 | 容器与部署 §5 |

## 执行纪律（四条，违反任一条先停）

1. **改配置先备份 + 可回滚**：动线上任何配置前 `cp a.conf a.conf.bak.$(date +%F-%H%M)`；给不出回滚命令的变更不许做。
2. **生产操作先预发演练**：发布/改参/扩缩容先在预发走完整流程（含回滚），预发跑不通不上生产。
3. **变更窗口意识**：高峰、大促冻结期、周五下午不发版；变更前记录 QPS/错误率基线，变更后 15 分钟内持续对比错误率。
4. **排障先看变更史**：出问题第一动作是翻最近 24-72h 变更（发布/配置/证书/扩缩/依赖升级），不是直接重启。

## 产物约定（每次变更/排障必须落盘）

1. **变更记录**（追加到任务目录 `变更记录.md`）：

| 字段 | 示例 |
|---|---|
| 时间/执行人 | 2026-10-10 14:00 / ops |
| 对象 | deploy/app：镜像 v1.2.3 → v1.2.4 |
| 变更内容 | 升级镜像；env 新增 FEATURE_X=true |
| 验证结果 | rollout status 完成；/healthz 200；错误率 0.1% |

2. **回滚步骤**（命令级，任何人可照抄执行）：
   - 回滚命令：如 `kubectl rollout undo deploy/app --to-revision=3`
   - 预期现象：2 分钟内错误率回落 < 1%，副本全 Ready
   - 回滚失败的升级路径：切流量到备用环境 / 值班联系人
   - 回滚步骤每季度在预发真跑一次演练，过期的当不存在

## 高频口令（最常用七条，先背这个再翻库）

| 口令 | 命令 |
|---|---|
| 看发布历史 | `kubectl rollout history deploy/<name>` |
| 一键回滚 | `kubectl rollout undo deploy/<name>` |
| 上次崩因 | `kubectl logs <pod> --previous --tail=100` |
| Pod 事件 | `kubectl describe pod <pod> \| grep -A10 Events` |
| 资源水位 | `kubectl top pod` |
| 端口连通 | `nc -zv <host> <port>` |
| 证书到期 | `openssl s_client -connect <host>:443 </dev/null 2>/dev/null \| openssl x509 -noout -dates` |

## 边界（不做什么）

- 不做集群搭建、内核调优等深水区（本技能到「业务稳定跑在集群上」为止）。
- 不覆盖有状态中间件自身运维（MySQL/ES 集群的 HA 与备份找专项）。
- 安全漏洞挖掘不在本技能范围（那是 SRC/白盒审计技能的事）。
